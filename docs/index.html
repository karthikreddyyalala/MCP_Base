Plain-English explanation

What does this
actually do?

The filing cabinet analogy
You hired a new employee and gave them a filing cabinet full of company documents. This tool is that cabinet, wired directly into Claude. Ask a question — it searches your actual files first, then gives you an answer with an exact citation. Like a librarian who says "page 47, third paragraph."
Term
MCP — Model Context Protocol
Anthropic's open standard that lets Claude Desktop talk to external tools. Like a USB port — you plug in a tool and Claude can use it. This project is one such tool, called an "MCP server."
Term
Semantic Search
Old search finds exact words. Semantic search understands meaning. "How do I fix a broken deploy?" finds "Rollback Procedure" — even though "fix" and "broken" don't appear in the title.
Term
Vector Embedding
Each document chunk becomes 384 numbers representing its meaning. Your query becomes numbers too. We find the chunks whose numbers are closest. That's semantic search under the hood.
Term
Citation [source: file.md:L18]
Every answer includes the exact file and line number. Open it, verify it, notice when docs are out of date. A system that gives answers without sources can't be trusted professionally.
Architecture

Five components.
One pipeline.

Here's exactly what each piece does, in plain terms.

01
Your markdown files
Put all your documentation in a folder — deployment guides, API references, onboarding docs. They're just regular .md text files. This is your raw knowledge.
./your-docs/*.md
02
The Indexer — index.py
Run once. Reads every file, cuts it into 400-word chunks with 50-word overlaps, then runs each chunk through all-MiniLM-L6-v2 — an AI model that converts text into 384 numbers representing its meaning.
python3 index.py --docs ./your-docs
03
ChromaDB — the vector store
All those number-lists get saved to a local database on your disk. ChromaDB is a filing cabinet that's very fast at finding "which documents have numbers closest to this search?" Nothing goes online.
~/.mcp-kb/chroma/ — local disk only
04
The MCP Server — server.py
Runs in the background, listens for Claude Desktop. Exposes two tools: search_docs (semantic search) and list_docs (show what exists). Speaks MCP protocol over stdio.
python3 src/server.py — stdio transport
05
Claude Desktop uses the tools
You ask "how do I roll back a bad deploy?" Claude calls search_docs, gets back 5 relevant chunks with file names and line numbers, then writes you an answer using that real information.
[source: deployment-runbook.md:L18-L24]

MRR@10 (Mean Reciprocal Rank) measures: when you search, does the right answer appear in your top 10 results — and how high up? Score of 1.0 = always first.

BM25, the same tech as old-school keyword search, scores 0.167. This project scores 0.585 — on 1.1 million real passages, 6,980 real queries from the MS MARCO benchmark.

Quickstart

Running in five
minutes.

Three commands to get Claude Desktop searching your docs.

Terminal
# 1. Clone and install
git clone https://github.com/karthikreddyyalala/MCP_Base.git
cd MCP_Base && pip install -e .

# 2. Index your docs (once)
python3 index.py --docs ./your-docs

# 3. Add to Claude Desktop
# ~/Library/Application Support/Claude/claude_desktop_config.json
{
  "mcpServers": {
    "knowledge-base": {
      "command": "python3",
      "args": ["/absolute/path/to/MCP_Base/src/server.py"]
    }
  }
}

# Restart Claude Desktop.
# Hammer icon appears → you're live.
# Ask: "What docs do you have access to?"
